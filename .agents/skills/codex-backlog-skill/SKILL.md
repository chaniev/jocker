# Обработка бэклога

Прочитать корневой и backlog/AGENTS.md, backlog/README.md и
 docs/requirements/README.md. Следовать выбранному пользователем объёму.

## Режимы

- Разбор входящих: обработать выбранные заметки; проверить дубликаты, но не
  проводить глобальный аудит статусов. Пустая очередь завершает разбор.
- Сверка статусов: проверить выбранные карточки по коду, тестам и main;
  не обрабатывать inbox без запроса.
- Полный проход: только при явном запросе обоих режимов, сначала сверка.

## Разбор

1. Сохранить исходный текст и дату; processing — временное место обработки.
2. Проверить совпадения в активных задачах, планах и рекурсивно в done.
   Уточнить существующую карточку или создать следующую JCR (продуктовую)
   либо TASK (техническую); не переиспользовать ID.
3. Записать проблему, ожидаемый результат, границы, критерии приёмки,
   зависимости, источник и вопросы. Можно использовать существующие JCR
   как образец. Добавить `- Статус:` и `## Requirements` по контракту реестра.
4. Выбрать статус по фактам: needs-clarification при отсутствии решения;
   tasks-ready при ясном результате и принятых требованиях; risky при
   конкретном риске потери данных, честности игры, совместимости или восстановления,
   который требует review. Указать механизм риска и условия продолжения.
   Модуль сам по себе не делает задачу рискованной.
5. Исходные заметки перенести в processed с сохранением текста; записать
   связи заметка → задача. Не терять необработанную часть файла.

## Сверка

Не считать готовый план или коммит в task-ветке доказательством завершения.
Проверить критерии, проверки и интеграцию в main. Для устаревшего состояния
записать основание исправления. Закрытую задачу и её план перенести вместе
по правилам даты done; исправить ссылки и индекс. Не угадывать неизвестные
решения или даты. Независимые карточки можно обработать при наличии блокеров.

## Результат

Обновить индекс и добавить запись в backlog/logs/triage-log.md: режим, область,
источники, изменения, причины пропусков, проверки; также фиксировать нулевой
результат. Запустить `make requirements-check` и проверки корневого harness.
Сообщить результат и ссылки без полного дерева бэклога. Не объявлять глобальную
сверку после проверки только выбранных задач.
